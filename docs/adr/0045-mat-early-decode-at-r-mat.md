# 0045. MAT에 실린 TrueHD는 중간 마커(R-MAT)에서 앞 절반을 먼저 디코드한다

상태: 채택, 2026-10-29.

## 배경

IEC 61937-9:2007(5.3.1, 5.3.2)에서 48 kHz MAT 버스트는 IEC 60958 프레임 15,360개마다 하나이고, 768 kHz 프레임 속도에서 20 ms입니다. 61,424바이트 페이로드에는 TrueHD 액세스 단위 24개(960표본)와 고정 기록 셋(시작 20바이트, 중간 12바이트, 끝 16바이트)이 있습니다. 규격은 중간 기록을 기준점 R-MAT로 두고 디코더 지연을 그 기준점부터 셉니다. 기준점 앞에 실린 액세스 단위는 R-MAT가 도착할 때 이미 다 들어와 있으므로, 수신기는 버스트 끝까지 기다리지 않고 앞 절반을 디코드할 수 있습니다. 사용자가 2026-10-29에 짚은 글(dcinside 스피커 갤러리 582547)도 이 기준점으로 실제 수신기의 지연을 설명합니다.

지금까지 엔진은 버스트가 다 들어온 뒤(Pa부터 61,432바이트) MAT 페이로드를 디코드 스레드에 넘겼습니다(ADR 0031). 앞 절반의 소리는 뒤 절반이 들어올 때까지 10 ms를 더 기다렸습니다.

## 결정

- 디프레이머는 MAT 페이로드가 중간 기록 끝(30,720바이트)에 닿으면 한 번 알립니다(`Deframer::push_with_partial`, `DeframeEvent::Partial`). 알림은 그때까지 받은 페이로드와 Pa의 위치를 담고, 할당하지 않습니다.
- 캡처 스레드는 그때 시작 기록과 중간 기록을 확인하고 앞 콘텐츠(20..30,708)를 `DeferredInput::TrueHdMat(MatPart::First)` 작업으로 넘깁니다. 버스트가 다 들어오면 길이와 세 기록을 확인하고 뒤 콘텐츠(30,720..61,408)를 `MatPart::Rest`로 넘깁니다. 두 작업은 이 순서로 큐에 들어갑니다.
- 중간 기록을 걸친 액세스 단위는 TrueHD 프런트가 앞 작업 끝에 남겨 두었다가 뒤 작업이 오면 한 번 디코드합니다.
- 앞쪽 기록이 틀리면 앞 작업을 넘기지 않습니다. 버스트가 다 들어온 뒤 전체 작업으로 넘기면, 디코드 스레드가 지금처럼 오류를 한 번 알리고 프런트를 초기화합니다. 앞 작업을 넘긴 뒤 뒤쪽 기록이 틀릴 때도 전체 작업으로 넘깁니다.
- 두 작업의 장면은 그 버스트의 Pa가 들어온 시각을 소스 시각으로 가집니다. 전체 작업의 장면과 같은 규칙입니다(`SceneBuffers::emit_range`: 버스트를 나눠도 더 늦은 시각을 지어내지 않는다). 그래서 측정한 지연은 조기 디코드로 앞당긴 만큼만 줄어듭니다. 작업마다 그 작업이 다 들어온 시각을 붙이면 10~20 ms가 더 준 것처럼 보이므로 그렇게 하지 않습니다(`early_mat_parts_keep_the_burst_arrival_time`).
- MAT 안의 비압축 PCM은 지금처럼 거절합니다. 앞뒤 콘텐츠 어디에도 TrueHD 주 동기가 없으면 뒤 작업이 `PCM inside MAT is not decoded yet`을 냅니다. PCM 디코드를 더할 때 같은 기준점에서 앞 절반을 먼저 냅니다.
- `ChainConfig::mat_early_decode`(기본 켬)를 끄면 전체 버스트 작업 하나로 돌아갑니다. 비교와 시험에만 쓰고 화면이나 명령줄에 내놓지 않습니다.

## 결과

- 각 버스트의 앞 절반은 Pa부터 30,728바이트째에 디코드 스레드로 갑니다. 전체 버스트를 기다릴 때보다 30,704바이트, 3,072,000바이트/초에서 9.99 ms 이릅니다. 드라이버는 1 ms마다 기록을 쓰므로 실제로는 R-MAT가 든 기록이 끝날 때 넘어가고, 1 ms 안에서 그만큼 늦습니다. 뒤 절반은 지금과 같은 때 넘어갑니다.
- 출력 표본은 켜고 끈 두 경우가 같습니다(`ssr-replay`의 렌더 바이트 비교, decode 크레이트의 표본 비교).
- MAT 버스트 하나가 작업 둘을 쓰므로, 디코드 스레드가 멈췄을 때 큐(16개)가 차는 시간은 320 ms에서 160 ms로 줍니다. 그만큼 멈추면 차선은 이미 소리가 끊긴 뒤이고, 거절된 버스트는 ADR 0031대로 차선을 다시 시작합니다. 그래서 큐는 늘리지 않습니다.
- 규격은 기준점 뒤 1/12 MAT 프레임(IEC 60958 프레임 1,280개, 약 1.67 ms)을 디코더 지연으로 둡니다. 우리는 앞 절반을 한 번에 디코드하고 그 장면을 10 ms 블록에 섞으므로 이 값보다 늦습니다. 액세스 단위마다 작업을 나누면 큐 작업이 버스트마다 24개가 되어 그렇게 하지 않았습니다.
- CI에는 MAT 소스가 없어(덤프 고정물은 FFmpeg로 만든 TrueHD 세 버스트뿐) 실제 드라이버에서 준 지연은 시험서명 PC의 보고서로 확인합니다.
